# P06.0 — Canvas schema in protocol

**App:** protocol (`packages/protocol`)
**Estimated effort:** 0.5 day
**Depends on:** P05A, P05B (need chat working before designing surfaces)
**Blocks:** P06A, P06B
**Can run in parallel with:** —

## Context

OpenClaw's docs mention "Canvas surfaces" for iOS/Android nodes but don't
spec the schema. We define the v1 schema here so mobile and desktop
renderers (P06A, P06B) build the same thing. Per `plan.md` §10, M4 and
`open-questions.md` §A6.

## Goal

A complete, Zod-validated v1 Canvas schema in `@openclaw/protocol` covering
the minimum useful set (heading, text, button, form field, list), plus a
patch format for live updates and an event format for user input.

## Inputs

- P01A (`@openclaw/protocol`) and downstream chat work complete enough that we understand what the gateway emits.

## Outputs

- `packages/protocol/src/canvas/types.ts` — TS types.
- `packages/protocol/src/canvas/schemas.ts` — Zod schemas.
- `packages/protocol/src/canvas/index.ts` — barrel.
- Tests covering construction + patch application + invalid-shape rejection.
- A short spec document at `packages/protocol/CANVAS.md` describing the schema for any agent author who wants to emit Canvas content.

## Steps

1. Define core types:
   - `CanvasSurface = { id, version, root: CanvasNode }`.
   - `CanvasNode = Heading | Text | Button | TextInput | Select | List | Stack`.
   - Each node: `{ type, id, ...props, children? }`.
2. Define patch format (JSON-patch–style or RFC 6902 subset):
   - `CanvasPatch = { surfaceId, ops: PatchOp[] }`.
   - `PatchOp = AddNode | RemoveNode | ReplaceProps | SetText`.
3. Define event format:
   - `CanvasEvent = { surfaceId, nodeId, type: "click" | "change" | "submit", payload }`.
4. Write Zod schemas mirroring each type.
5. Implement `applyPatch(surface, patch): CanvasSurface` as a pure function.
6. Tests:
   - Round-trip: construct surface → encode → decode → equal.
   - Apply patch: add/remove/replace ops produce expected result.
   - Invalid shapes rejected with informative error.
7. Write `CANVAS.md` with:
   - One-paragraph overview.
   - JSON examples for each node type.
   - Patch examples.
   - Event payload examples.
8. Update `packages/protocol/src/index.ts` to export Canvas types/schemas/helpers.

## Notes

- **Resist over-design.** v1 is 6 node types and 4 patch ops. We can add more after a real agent uses Canvas in anger.
- The schema should be **agent-emittable** — keep field names short and stable.
- File a PR or issue against `openclaw/openclaw` proposing this schema upstream once it lands. The plan owner does that, not the executing agent.
- Do **not** implement renderers here. P06A/P06B.
