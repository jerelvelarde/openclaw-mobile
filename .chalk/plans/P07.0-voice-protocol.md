# P07.0 — Voice transport decision + protocol extension

**App:** protocol (`packages/protocol`)
**Estimated effort:** 0.5 day
**Depends on:** P05A, P05B (chat done; we know what we're extending)
**Blocks:** P07A, P07B
**Can run in parallel with:** —

## Context

Decide between **frames-over-WS** (simple, lower quality, easier in
backgrounded RN) and **WebRTC** (better quality, lower latency, but needs
custom dev client + signaling). Per `open-questions.md` §A7 and
`host-target.md` (the Mac mini's strong WebRTC support makes WebRTC viable).

## Goal

Decision recorded, voice protocol extended in `@openclaw/protocol`, and a
short spec written so P07A/P07B can build to the same wire format.

## Inputs

- Existing chat + transport working end-to-end.

## Outputs

- `packages/protocol/src/voice/types.ts`
- `packages/protocol/src/voice/schemas.ts`
- `packages/protocol/VOICE.md` — decision + protocol spec.
- Updated `packages/protocol/src/index.ts` barrel.
- Tests covering envelope decoding for voice frames / signaling messages.

## Steps

1. Decide WebRTC vs WS-frames. Default recommendation: **WebRTC for v1**, because:
   - The host is always a Mac (strong WebRTC support).
   - Latency matters for natural voice interaction.
   - iOS background audio is doable with WebRTC + CallKit/PushKit (out of scope for v1, but the path is clearer).
   - Fallback to WS-frames remains possible per-call.
2. Define types:
   - `VoiceOpts = { agentId, format: "opus" | "pcm16", sampleRate }`.
   - For WebRTC: `VoiceSignal = { type: "offer" | "answer" | "ice", sdp?, candidate? }`.
   - For frames-over-WS fallback: `VoiceFrame = { seq, data: Uint8Array }`.
   - `VoiceTranscript = { text, isFinal, ts }`.
3. Define topics:
   - `voice.<sessionId>.signal` (WebRTC signaling).
   - `voice.<sessionId>.frame` (WS-frame fallback).
   - `voice.<sessionId>.transcript` (live transcript from agent).
4. Write Zod schemas.
5. Write `VOICE.md`:
   - Decision rationale.
   - Sequence diagram for WebRTC handshake (mobile/desktop → gateway → agent).
   - Fallback flow for WS-frames.
   - Agent-author notes (what they need to handle).
